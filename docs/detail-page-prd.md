## 1. 产品目标

**一句话**：把股票详情页从「历史数据的静态陈列」，改造成**「盘中能据此下单的分时决策台」**——打开页面第一眼就看到 AI 结论与「加仓/减仓/观望」三选一，中部是 VWAP、量比、主力净比、板块情绪构成的分时决策面板，并让 MACD/KDJ、量比这些**已经算好却从没露面**的数据真正上屏。

**改完的具体差异**：

| | 现在 | 改完 |
| --- | --- | --- |
| 结论 | 要点「AI 分析」按钮开弹窗才看得到 | 首屏顶部直接展示结论卡片 |
| 决策依据 | 均线 + 日级资金流（滞后 1 天） | 当日 VWAP + 量比 + 主力净比 + 板块情绪（盘中实时） |
| MACD/KDJ | 算了、下发了、AI 用文字说了，但页面上一个字没有 | 独立区块 + 图 |
| 量比 | 首页有，详情页没有 | 详情页分层高亮 |
| 操作建议 | 无 | 三选一 + 价格止损位 + 时间止损条件 |

### 2.2 关键实测证据（2026-09-01 盘中，000001 平安银行）

**① VWAP 精度——实时行情口径与 1 分钟线逐根累加完全一致**

| 计算口径 | VWAP | 与真值偏差 |
| --- | --- | --- |
| 226 根 1 分钟线逐根累加（**真值**） | 11.8618 | — |
| **实时行情 `amount ÷ volume`** | **11.8621** | **+0.003%** |
| 当日 4 根 60 分钟线累加 | 11.8618 | 0.00% |
| 全部 24 根 60 分钟线累加（**现状数据口径**） | 11.6854 | **−1.49%** ❌ |

**② 板块行情零成本可得**——现有 slist 请求字段为 `f12,f13,f14,f3`，但代码**只取了 `f14` 名称，把 f12/f13/f3 全丢了**：

```
f12(板块代码)=BK0475  f13(市场)=90  f14(名称)=银行Ⅱ  f3(涨跌幅)=1.97
f12=BK1610  f13=90  f14=股份制银行Ⅲ  f3=1.75
f12=BK0153  f13=90  f14=广东板块     f3=-0.08     ← 地域伪板块
f12=BK0500  f13=90  f14=HS300_       f3=0.13      ← 指数伪板块
```

用 `secid=90.BK0475` 走**现有 stock/get 单券通道**可拿完整板块行情：
`最新价=4384.13 最高=4393.99 最低=4287.27 今开=4290.33 昨收=4299.41 涨跌幅=1.97% 换手率=0.41% 量比=1.43 成交额=399.2亿`
（板块涨跌幅 f3=1.97 与 stock/get 的 f170=1.97 **完全一致，可互相校验** ✅）

**③ 主力资金字段可得**：`f62`(主力净流入)=60,196,496 元、`f184`(主力净占比)=**3.51**（600519 对照：f184=5.5）。
**④ 板块主力资金不可用**：板块 secid 走 stock/get 时 `f62=0`，**板块层面无资金流数据**，情绪周期不得使用板块资金指标。
**⑤ 1 分钟 K 线可用**：`klt=1, lmt=240` 实测返回 226 根（09:31~14:46 实时增长），字段含 amount/volume，可画标准分时图。
**⑥ 涨红跌绿已统一**：`charts.js:5-6` `UP='#f5465d'`（红）/ `DOWN='#17b26a'`（绿）。

### 2.3 对既有诊断的两点修正

1. **`oscillators` 不是纯浪费**：`rule_engine.py:487` 用它评分、`prompts.py:402` 喂给 LLM。真正的浪费在**UI 层**——算了、下发了、AI 用文字说了，但详情页一个字没显示。所以「补齐」= **补 UI 展示**，零新增计算成本。
2. **`kline_min` 的上游请求不是浪费**：后端 `intraday_trend_state()` 用它产出「趋势状态·盘中 +1.71%」标签。真正浪费的是**下发给前端的 24 根原始 bars 从未被渲染**（约 3–4KB/次，盘中每 30s 重取）。处理办法二选一：渲染成分时图，或停止下发（后端内部仍用）。

### 2.4 已有能力复用（不要重复造）

- **`intraday_state_from_quote()`（indicators.py:968）已经是分时决策体系的雏形**：它已按「盘中位置 × 涨跌方向」「量比 × 涨跌方向」「振幅」输出`放量上攻 / 冲高回落 / 弱势探底 / 空头衰竭`等标签，且已作为「盘口位置」标签显示在状态区。
  → **新增的分时决策区块应当消费并扩展它，而不是另起一套评分**，否则会出现同一页两套口径打架。
- **性能开关已实现，不要重复造**：非交易时段停止轮询（`session.auto_refresh=false` → `tick()` 早退）；页面不可见暂停（`app.js:142` `if (document.hidden) return;`）；恢复可见立即补一次（`app.js:606` visibilitychange）。

## 3. 用户故事

### 方向一：接入分时决策体系（P0，用户标记「推荐」）

1. 作为 A 股短线交易者，我希望**在详情页顶部直接看到「加仓 / 减仓 / 观望」三选一及其触发条件**，以便不用自己拼散落指标就能立刻执行，而不是读完一堆指标还得自己下结论。
2. 作为 A 股短线交易者，我希望看到**现价相对当日 VWAP 分时均价线的位置与偏离幅度**，以便判断今天是强势在均价上方运行，还是弱势在均价下方挣扎。
3. 作为 A 股短线交易者，我希望**量比和主力净比按分层阈值高亮**（而不只是一个数字），以便在放量/缩量、主力进/出的关键档位被明确提示。
4. 作为 A 股短线交易者，我希望看到**个股相对所属板块的强弱（超额涨跌）**，以便知道这只票是板块龙头，还是板块拖后腿的跟风股。
5. 作为 A 股短线交易者，我希望系统明确给出**价格止损位与时间止损条件**，以便在走势变坏时有可执行的退出纪律，而不是「再看看」。
6. 作为 A 股短线交易者，我希望**板块情绪周期（启动/发酵/高潮/退潮）被明确标注**，以便决定现在是该追、该持有还是该撤。
7. 作为 A 股短线交易者，我希望**均线不再被当作主判断依据**（A 股板块轮动极快，单日或 2–3 天即切换，5/10 日均线严重滞后），以便不被滞后信号误导。

### 方向二：补齐已算未用数据

8. 作为用户，我希望 **MACD/KDJ 的计算结果直接显示在详情页**，以便不用点开 AI 分析、从大段文字里找「金叉/死叉」。
9. 作为用户，我希望**量比在详情页显示**（首页已有），以便判断当前成交活跃度。
10. 作为用户，我希望**已下发的 60 分钟 K 线要么被画成分时图、要么不再下发**，以便不为看不见的数据付带宽。

### 方向三：性能与体验

11. 作为用户，我希望**新增分时决策能力后详情页首屏仍然秒开**，以便不牺牲现有体验。
12. 作为用户，我希望**分时决策区块在数据缺失时明确说明原因**，以便不会把「没数据」误读成「没信号」。
13. 作为用户，我希望**在非交易时段、切到后台时页面自动停止请求**，以便不浪费流量和数据源配额。（现状已实现，本轮需回归验证不退化）

### 方向四：顺带优化 AI 分析展示

14. 作为用户，我希望 **AI 结论前置在详情页顶部，而不是藏在弹窗里**，以便打开页面第一眼就看到结论。
15. 作为用户，我希望**置信度以「低/中/高」分档 + 明确免责说明呈现**，以便不被一个**方向性已被回测证伪**的评分用高置信度误导。
16. 作为用户，我希望知道**结论来自 LLM 还是规则引擎、数据是否过期**，以便判断该信几分。

### 4.4 降级与空态规则

| 场景 | 表现 |
| --- | --- |
| 非交易时段 | 分时决策面板显示最近交易日收盘值，标题加「（09-01 收盘）」后缀；VWAP/量比/主力净比仍展示，不作实时暗示 |
| 盘前 9:30 前 | 整块灰显 + 「待开盘，分时指标将在开盘后实时更新」 |
| 某字段缺失（如主力净比 null） | 该格显示 `—` + tooltip 说明原因（如「行情源未提供」），**不得显示 0、不得塌陷、不得隐藏整块** |

| 数据延迟（status=delayed） | 面板加黄条「数据更新延迟（最新交易日 09-01）」，数值照常展示但不高亮触发条件 |

## 5. 需求池

> 标记说明：`[前端]` / `[后端]` / `[前+后]`
> **P0 = 本次必做**，P1 = 本次尽量做，P2 = 后续迭代

### P0（必做）

| ID | 端 | 需求 | 验收标准 |
| --- | --- | --- | --- |

## 6. 板块情绪周期四阶段 · 判定规则草案

### 6.1 可用数据（均已实测可得）

| 输入 | 来源 | 成本 |
| --- | --- | --- |
| 板块当日涨跌幅 `board_chg_pct` | slist `f3`（P0-3 带出） | 零新增请求 |
| 板块量比 `board_volume_ratio` | stock/get `f50` 走 `90.BKxxxx`（P1-1） | +1 次请求 / 1h 缓存 |
| 板块换手率 `board_turnover` | stock/get `f168`（P1-1） | 同上 |

| ~~板块主力资金~~ | 实测 `f62=0`，**板块层面不可用** | — |
| ~~板块内涨停家数~~ | 当前无数据源 | — |

### 6.2 判定规则（v1 草案）

**匹配顺序：退潮 → 高潮 → 发酵 → 启动 → 震荡**（先判极端态，避免中间态被先匹配）

| 阶段 | 判定条件（满足任一即可） | 页面话术 | 对个股仓位含义 |
| --- | --- | --- | --- |
| **退潮** | 当日 chg ≤ −1.5% 且 量比 < 0.8；**或** 近 5 日累计 ≤ −3% 且 当日 chg < 0 | 板块走弱，个股逆势难度高 | 上限 3 成，减仓优先 |
| **高潮** | 当日 chg ≥ +3% 且 量比 ≥ 1.5；**或** 近 5 日累计 ≥ +8% 且 量比 ≥ 2.0 | 板块过热，追高风险大 | 不新开仓，可分批减 |
| **发酵** | 当日 chg ≥ +1% 且 量比 ≥ 1.0；**或** 近 5 日累计 ∈ [+2%, +8%) 且 当日 chg > 0 | 板块正在走强 | 可持有，回踩可加 |
| **启动** | 当日 chg ∈ [0, +1%) 且 量比 ≥ 1.2；**或** 近 5 日累计 ∈ [0, +2%) 且 量比 ≥ 1.0 且 当日 chg > 0 | 板块刚起步 | 轻仓试探 |
| **震荡** | 以上均不匹配 | 板块无明显方向 | 个股独立行情为主 |

### 6.3 三条设计原则（重要）

1. **板块阶段 ≠ 个股操作建议**。个股建议 = **板块阶段**（决定仓位上限）× **个股相对强弱**（决定加减）× **分时位置**（决定时机）。三者是乘法关系，不是取其一。
2. **只作仓位上限约束，不作唯一开关**。板块退潮时龙头股仍可能独立走强，所以规则输出的是「上限 3 成」而非「必须清仓」。
3. **阈值是可调参数，不是真理**。草案阈值是通用值，需用户按自身经验校准（见 Q2），建议做成可配（P2-3）。

### 7.1 现状核查：两个问题都已实现，本轮不重复造

| 页面不可见是否暂停？ | ✅ **已暂停** | `app.js:142` `if (document.hidden) return;`；`app.js:606` visibilitychange 恢复可见时立即补一次 tick |

### 7.2 本轮性能红线（新增能力不得新增请求）

**P0 全部分时决策能力，新增上游 HTTP 请求数 = 0**：

| 能力 | 请求增量 | 做法 |
| --- | --- | --- |
| VWAP | **0** | 现有 `quote.amount ÷ quote.volume` |
| 量比 | **0** | 现有 `Quote.volume_ratio` |

| 1 分钟分时曲线 | **+1**（或替换 klt=60 则 0） | 仅 P1-7 |

### 7.3 必须遵守的四条规则

1. **新数据必须并入现有并发组**：任何新增取数放进 `stock_detail` 的 `asyncio.wait` tasks 里，**禁止串行 await**，保持 `FIRST_EXCEPTION` 语义。
2. **分时面板不进全量重渲**：见 P1-5。5 秒 tick 只 patch 随行情变化的字段。
3. **分时曲线绝不进 5 秒 tick**：240 根 bars 每 5 秒传一次是纯浪费，仅 mount / 手动刷新拉取，tick 只追加最新一根。
4. **砍掉纯浪费的响应体**：P1-6（停发未渲染的 `kline_min` bars）与 P1-7（渲染成分时图）**二选一**，不允许「既下发又不渲染」的状态长期存在。
